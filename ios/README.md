# Space Harmony — iOS App (MVP)

A native iOS wrapper around the existing [orbital-harmony-app](../orbital-harmony-app)
React + Three.js web experience. This is an MVP: rather than reimplementing the
3D solar-system engine natively (a much larger effort), the app embeds the
existing web build inside a `WKWebView`, giving a real installable iOS app
with the full existing experience (Solar System browse, planet selection,
live pattern simulation, PNG results) and no network dependency for its core
assets.

## How it works

- The Xcode project itself (`OrbitalHarmony.xcodeproj`) is **generated** from
  [`project.yml`](project.yml) using [XcodeGen](https://github.com/yonaskolb/XcodeGen)
  rather than hand-authored — this keeps the project file reproducible and
  diff-friendly (the `.xcodeproj` is not the source of truth, `project.yml` is).
- `OrbitalHarmony/Resources/www` contains a copy of the web app's production
  build (`orbital-harmony-app/dist`, i.e. the output of `npm run build`).
- `WebView.swift` loads that bundle through a **custom `orbital://` URL
  scheme** (`LocalFileSchemeHandler.swift`) instead of a plain `file://` load.
  This matters because the web app's planet data
  (`orbital-harmony-app/src/data/planets.js`) references texture assets by
  **absolute root path** (e.g. `/textures/mercury.jpg`) — under a plain
  `file://` load those would resolve to the real filesystem root and 404
  (blank/untextured planets). Serving everything from a fixed origin
  (`orbital://app/...`) makes absolute-path references resolve correctly
  back into the bundled files, the same trick hybrid-app frameworks like
  Capacitor/Cordova use under the hood.

## Prerequisites

- A Mac with **Xcode installed** (this was generated/validated in an
  environment with only Xcode Command Line Tools, not full Xcode — you'll
  need to open and build it in real Xcode yourself; the generated project
  files were validated as well-formed but not yet compiled).
- [XcodeGen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`
- Node.js + npm (already required by `orbital-harmony-app`).

## First-time setup

```sh
cd ios
./scripts/rebuild-web.sh   # builds the web app and generates OrbitalHarmony.xcodeproj
open OrbitalHarmony.xcodeproj
```

In Xcode:
1. Select the `OrbitalHarmony` target → **Signing & Capabilities** → choose
   your own Team (Automatic signing is already enabled in `project.yml`).
2. Pick any iPhone simulator (or a real device) and press **Run**.

## Updating after web app changes

Whenever you change anything under `orbital-harmony-app/src`, re-run:

```sh
./scripts/rebuild-web.sh
```

This rebuilds the web app, refreshes `OrbitalHarmony/Resources/www`, and
regenerates the Xcode project. Then just re-run in Xcode.

## Project layout

```
ios/
  project.yml                  # XcodeGen spec — source of truth for the Xcode project
  scripts/rebuild-web.sh        # rebuilds the web app + regenerates the .xcodeproj
  OrbitalHarmony.xcodeproj/     # generated by xcodegen — do not hand-edit
  OrbitalHarmony/
    App/
      OrbitalHarmonyApp.swift       # @main SwiftUI app entry
      ContentView.swift             # full-screen container hosting the WebView
      WebView.swift                 # UIViewRepresentable WKWebView wrapper
      LocalFileSchemeHandler.swift  # serves Resources/www via orbital://app/...
    Resources/
      Info.plist                    # hand-authored (portrait-only, dark launch bg, etc.)
      Assets.xcassets/               # AppIcon, AccentColor, LaunchBackground color
      www/                           # copy of orbital-harmony-app/dist (regenerated by script)
```

## Known limitations (MVP scope)

- **Fonts**: the app's two Google Fonts (Exo 2, Orbitron) are still loaded
  from `fonts.googleapis.com` over the network, same as the web version —
  if the device is offline on first load, the app falls back to the system
  font (already handled by the existing CSS `font-family` fallback stack).
  Bundling the font files locally for full offline support is a reasonable
  v2 follow-up.
- **Download PNG / Share**: these use standard web APIs (an anchor-download
  and `navigator.share`) which work in a real mobile browser, but haven't
  been specifically wired up to native "Save to Photos"/share-sheet
  integration inside the WKWebView wrapper yet — treat this as a v2 polish
  item, not a blocker for the MVP (viewing/generating patterns is the core
  experience and works end-to-end).
- **iPhone only**: `TARGETED_DEVICE_FAMILY` is set to iPhone only, matching
  the web app's own mobile-first design; iPad support isn't in scope for
  this MVP.
- **Not yet compiled**: this project was generated and its files validated
  (well-formed `project.pbxproj`, `Info.plist`, and `.xcscheme`) in a
  sandboxed environment with only Xcode Command Line Tools installed, not
  full Xcode — so it could not actually be compiled/run here. It should
  open and build normally in real Xcode; if anything doesn't, most likely
  causes are a signing team not yet selected or an Xcode version mismatch
  in `project.yml`'s implicit settings.
